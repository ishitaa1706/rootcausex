# Claude Rules — RootCauseX

Before implementing anything:

ALWAYS read:
- docs/rootcausex-context.md
- docs/current-state.md

Understand:
- current architecture
- current implementation state
- existing constraints

---

# Project Philosophy

RootCauseX is:
- an AI-native runtime investigation platform
- a conversational production debugging system

It is NOT:
- a monitoring dashboard
- a rollback system
- a DevOps platform
- a Kubernetes tool

Focus on:
AI-powered runtime reasoning.

---

# MVP Constraints

DO NOT introduce:
- databases
- Kubernetes
- authentication
- microservices
- Kafka
- Docker complexity
- real telemetry ingestion
- unnecessary abstractions

Keep implementation:
- modular
- hackathon-friendly
- visually impressive
- easy to demo

---

# Implementation Priorities

Prioritize:
1. visible outcomes
2. demo experience
3. runtime storytelling
4. AI interaction
5. smooth UX

NOT:
- production readiness
- scalability
- enterprise security
- optimization

---

# Frontend Rules

Frontend should feel:
- cinematic
- futuristic
- AI-native

Use:
- glassmorphism
- glowing effects
- smooth animations
- dark observability-inspired UI

---

# Backend Rules

Backend should:
- use mock runtime data
- expose clean APIs
- simulate believable runtime behavior
- support anomaly detection

Keep backend simple.

---

# AI Rules

AI should:
- reason about runtime context
- correlate anomalies
- explain probable causes
- feel intelligent

AI should NOT:
- hallucinate unrealistic infrastructure
- pretend to have real telemetry
- fabricate unsupported incidents

---

# Architecture Rules

DO NOT:
- rewrite architecture
- introduce new frameworks
- restructure the entire project
- overengineer abstractions

Preserve:
- current architecture
- current MVP scope
- implementation simplicity
